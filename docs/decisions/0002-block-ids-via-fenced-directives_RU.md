# 0002: Идентификаторы блоков через ограждённые директивы в Markdown

[English](0002-block-ids-via-fenced-directives.md) · [**Русский**](0002-block-ids-via-fenced-directives_RU.md)

## Контекст (Context)

Noetec трактует документы как деревья блоков (абзацы, заголовки, задачи, списки, блоки кода), и более поздние фазы требуют операций на уровне блоков, журнала операций на уровне блоков и слияния на уровне блоков при синхронизации. Всё это зависит от того, есть ли у каждого блока стабильный уникальный идентификатор. В то же время формат хранения Noetec — обычный человекочитаемый markdown, который должен оставаться редактируемым во внешних редакторах и переживать round-trip (разбор → правка → сериализация) без потери информации об идентичности.

У обычного markdown нет родного способа прикрепить идентификатор к блоку, поэтому нужна явная внутрифайловая (in-band) кодировка.

## Решение (Decision)

Дать каждому блоку уникальный ID, закодированный прямо в исходнике markdown с помощью ограждённых контейнерных директив вида `::: <type> <id> ...other attrs` … `:::`. Открывающее ограждение каждого блока несёт его тип и уникальный ID (плюс необязательные атрибуты, например статус задачи); вложенные блоки вкладывают свои ограждения. Идентификаторы блоков сохраняются через round-trip разбор → сериализация, поэтому идентичность переживает сессии редактирования.

## Статус (Status)

Принято (Accepted).

## Последствия (Consequences)

- Положительно: идентичность блока хранится внутри файла, который читает пользователь, — никаких побочных файлов или внешнего индекса, которые могут разойтись с содержимым.
- Положительно: ID переживают round-trip и внешние правки, что позже делает возможными стабильный дифф на уровне блоков, журналы операций и слияния.
- Положительно: файл остаётся обычным текстом и дружелюбен к контролю версий.
- Отрицательно: синтаксис директив — нестандартный markdown; редакторы, которые о нём не знают, покажут ограждения как видимый текст.
- Отрицательно: парсер и сериализатор должны корректно обрабатывать директивы (включая вложенность), а некорректные ограждения из внешних правок должны переноситься мягко.

## Рассмотренные альтернативы (Alternatives considered)

- **Без явных ID (позиционная идентичность)** — отклонено: идентичность блока по позиции ломается при переупорядочивании и одновременных правках, что делает надёжные операции на уровне блоков и слияния невозможными.
- **Маркеры в HTML-комментариях (например, `<!-- id: xyz -->`)** — отклонено: визуально навязчивее в исходном markdown, легче случайно удалить и неудобнее связывать с вложенной структурой блоков, чем парные открывающие и закрывающие ограждения.
- **Внефайловое отображение ID (отдельный индексный файл)** — отклонено: дублирует состояние, рискует расхождением между индексом и фактическим содержимым файла и ломается, когда файл правят извне без обновления индекса.
