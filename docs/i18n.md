# Documentation languages

[**English**](i18n.md) · [Русский](i18n_RU.md)

Noetec keeps its documentation in English and ships a Russian translation of every
document next to it. English is canonical: the Russian file is a translation, never
a second source of truth. This document defines how the two are paired, what the
switcher looks like, what a translator may and may not change, and how the pairing
is checked.

## Languages

- **English** — the source language and the only version that is authoritative. A
  change lands in English first.
- **Russian** — a full translation of the document it sits next to. It never
  introduces content the English file does not have.

Both files are versioned in the same repository, merged in the same pull request,
and reviewed together.

## The language switcher

Every document — English and Russian alike — starts with the same one-line switcher
directly under its H1:

```markdown
# Roadmap

[**English**](ROADMAP.md) · [Русский](ROADMAP_RU.md)

## Status
```

In the Russian file the bold entry is the Russian one, and the English entry links
back to the original:

```markdown
# Дорожная карта

[English](ROADMAP.md) · [**Русский**](ROADMAP_RU.md)

## Статус
```

Rules for the switcher:

- Two entries, always in this order: English first, then Русский.
- The current language is bold and still a link, so each file links to itself and
  to its translation, and the two files of a pair show the same set of links.
- One blank line between the H1 and the switcher, one blank line after it.
- `·` (U+00B7 MIDDLE DOT) as the separator, single spaces around it.
- Plain Markdown only: no shields.io badges, no emoji, no HTML, no
  "Languages:"/"Языки:" label, no blockquote marker. Badges need an external image
  service and render inconsistently in IDEs and plain viewers.

## File layout

A translation lives in the same directory as its source, with `_RU` appended to the
file name before the extension:

| Source | Translation |
|---|---|
| `README.md` | `README_RU.md` |
| `docs/architecture.md` | `docs/architecture_RU.md` |
| `docs/decisions/0007-user-device-identity-and-registry.md` | `docs/decisions/0007-user-device-identity-and-registry_RU.md` |

Files that are not translated, and why: `LICENSE` (the AGPLv3 text is legally
binding and stays verbatim), `.github/` (GitHub templates and platform metadata),
`skills/` (agent runtime instructions), `test/` and `test_data/` (golden fixtures
whose exact content the tests assert), and platform asset notes such as
`ios/Runner/Assets.xcassets/LaunchImage.imageset/README.md`.

## Rules for translators

### Structure

- Same section order, same number of headings, tables, fenced code blocks and
  examples as the source. No section added, removed, merged or reordered.
- No new examples, no added explanations, no omissions. A visibly shorter
  translation is a defect, not an editorial improvement.
- Technical Russian, no marketing tone, no added emphasis.

### What stays untranslated

Byte-for-byte identical to the source: inline code, identifiers and API names
(`VaultSystem`, `command.run(param)`), file paths, CLI commands, URLs, YAML and
JSON samples, block directives (`::: {#block-id}`), hashes (`sha256:<hex>`),
version numbers, ADR numbers and PR/issue keys.

Fenced code blocks keep their contents verbatim, with one exception: when a block
is a diagram, a directory tree or an annotated example, its human-readable
annotations may be translated. Paths, identifiers, commands and program output
inside such a block stay verbatim, and the alignment and box-drawing characters
must be preserved so the picture still lines up.

### Normative keywords

Specifications and ADRs use the RFC 2119 keywords. They stay uppercase English,
with a Russian gloss in parentheses at first use in each section:

| Keyword | Gloss |
|---|---|
| `MUST` | (обязательно) |
| `MUST NOT` | (запрещено) |
| `SHOULD` | (следует) |
| `SHOULD NOT` | (не следует) |
| `MAY` | (допускается) |

A translation never weakens or strengthens a normative statement: if the source
says an implementation **MUST** reject an entry, the Russian text must say the same
thing with the same force.

### ADR and changelog headings

Architecture Decision Records keep their skeleton recognisable by making the
headings bilingual:

- `## Контекст (Context)`
- `## Решение (Decision)`
- `## Статус (Status)`
- `## Последствия (Consequences)`
- `## Рассмотренные альтернативы (Alternatives considered)`

Status values are bilingual too: `Принято (Accepted)`, `Предложено (Proposed)`,
`Заменено (Superseded by ADR-NNNN)`.

The changelog follows Keep a Changelog, so its section labels are bilingual:
`### Добавлено (Added)`, `### Изменено (Changed)`, `### Исправлено (Fixed)`,
`### Удалено (Removed)`.

### Links and anchors

- A relative link to another document points at that document's translation
  (`../CHANGELOG_RU.md`, `docs/specs/sync-security_RU.md`). The only English
  document a Russian file links to is its own original, in the switcher.
- Links to non-document targets — `LICENSE`, source paths, images, external URLs —
  are left as they are.
- An in-document anchor (`#heading`) is recomputed for the translated heading and
  must resolve to a heading in the same file. GitHub slugs lowercase the heading,
  drop punctuation and turn spaces into hyphens, keeping Cyrillic letters.

## Checking a translation

`scripts/check_docs_i18n.dart` verifies the mechanical part of this document: the
pair exists, both switchers are exact, heading and fenced-block counts match, the
Russian file is not suspiciously short or long, every relative document link
resolves, and every in-document anchor matches a heading.

```bash
dart run scripts/check_docs_i18n.dart              # report; untranslated files are warnings
dart run scripts/check_docs_i18n.dart --require-all # also fail when a pair is missing
```

The check runs on every documentation pull request; `--require-all` is the
acceptance gate for full coverage.

## Keeping translations current

- A documentation change is made in both languages in the same pull request. An
  English-only change with a stale or missing Russian counterpart is a review
  blocker.
- A new document is added together with its `_RU` file and the switcher in both.
- Renaming a document renames its translation too; the switcher in the pair is
  updated in the same commit.
- Correcting a translation is a normal documentation change: it follows this
  document and does not need a new ADR.

## Adding a new document

1. Write the English document, with the switcher directly under its H1.
2. Add the Russian translation next to it, with the same switcher mirror image.
3. Use the glossary for domain terms; extend it in both languages if a new concept
   appears.
4. Run `dart run scripts/check_docs_i18n.dart --require-all` and fix what it
   reports.
5. Mention both files in the pull request so a reviewer sees the pair.
